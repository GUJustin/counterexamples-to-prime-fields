## Limits and small improvements

1. The finite checks supplement proofs. Generic-rank upper bounds and general
   proximity theorems remain cited mathematical inputs. Deterministic samples
   exhaust parameters and codewords within their chosen instances, not every
   possible domain, affine pencil or polynomial curve.
2. The verifier correctly separates general interval-code list certificates
   from claims about the fixed better.codes domain. A larger interval-code list
   lower bound does not by itself certify a better submission.
3. Historical appendix models are excluded from `make verify`; their saved
   outputs were not revalidated by this run. Two source-inspection scripts use
   an absolute path to the original proving-source checkout, as the README
   already explains. No fixed-verifier acceptance or Fiat–Shamir distribution
   conclusion follows from these eleven coding checks.
4. `verify_weights.py` uses each certificate's saved center and support endpoints,
   without asserting that they equal the recomputed conditional-moment center
   and extrema. All ten entries were checked manually in this audit and are
   correct: center `22138`, support `[17969,26129]`. Adding these cross-file
   assertions would make future certificate changes easier to verify safely.
5. `make verify` rewrites result JSON. The only tracked difference generated by
   this run is `checks/conditional_moment_results.json`'s
   `certificate.elapsed_seconds` (from `2.9765918330522254` to
   `4.754709666012786`). Mathematical values are unchanged. Keeping elapsed
   timings in console output instead of the checked-in result would make the
   output byte-for-byte reproducible.

No tracked source files were deliberately edited in this audit. The timing-only
result difference was left for the root editor to discard or retain explicitly.

## Follow-up verifier hardening

After the audit, the root editor authorized a change to
`moment_certificates/verify_weights.py`. It now independently recomputes
conditional second-moment extrema, validates that recurrence against the
existing exhaustive small histograms, and requires every saved certificate's
support and center to match the independently checked metadata. It also checks
moment-vector and coefficient lengths, degree limits, and the exact coefficient
identity obtained by multiplying each factored certificate's roots.

The timing-only JSON change described above was restored by replacing only its
known elapsed-time field, preserving all other file content. No certificate
metadata were changed to satisfy the new assertions.

The targeted `python3 moment_certificates/verify_weights.py` run passed with
these changes, reproducing all 20 certificates and the same best bound. Its
result JSON remained byte-for-byte unchanged.
